# 問題の見直し記録

問題を追加・修正したときは、必ず次の2つの工程を通す。

## 見直しの手順

### 工程1: 機械チェック(スクリプト)

```bash
node scripts/check.js <過去問テキストのフォルダ>
```

チェックする内容:
- 形式: ID の重複、項目の抜け、分野名と ID の略号のずれ、問題文の重複
- ○×と解説の食い違い: 答えが○なら解説は「正しい。」で、×なら「誤り。」で始まっているか
- 過去問との重複(著作権対策): 問題文・解説に、R5〜R7過去問と20文字以上一致する部分がないか
- バランス: 分野ごとの問題数と、○×の割合(30〜70%の範囲に収まっているか)

過去問テキストは、PDF から pypdfium2 で抽出したもの(R5〜R7)。プロジェクトには置かない。
フォルダを指定しないときは、過去問との重複チェックだけを飛ばす。

### 工程2: 内容の見直し(1問ずつ)

1. 法令の基準日(2026/4/1)時点で正しいか
2. ○×が一つに決まるか(例外があって答えがぶれないか)
3. 根拠の条文番号は合っているか
4. 過去問の選択肢と、内容・言い回しが近すぎないか

### 確認しきれていない点(要注意)

- **区分所有法(ken-041, ken-042)**: 2026年4月1日に施行された区分所有法の改正(集会の決議要件の見直しなど)が、この2問に影響しないことを条文で確認できていない。決議要件の数字を問う問題は、意図的に入れていない。
- **根拠の表記**: 告示や規約の「第○」などの細かい番号は、手元で原文と照合していない。
- **統計問題**: 毎年変わるため、収録していない。

## 今後の追加・修正のときのルール

- 問題は条文・制度の事実から書き下ろす。過去問の選択肢を見ながら書かない
- 修正したら `sw.js` の VERSION を上げる(スマホに保存された古いデータを入れ替えるため)
- この記録に、日付・ID・修正内容を書き足す
